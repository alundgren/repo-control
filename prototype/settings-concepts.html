Where settings should live

Three directions for ignoring repositories today without boxing in label-to-queue rules tomorrow.

Desktop + narrowComplete ignore and restore flowSeptember 2026

The design target

This setting changes the work list, not just a preference.

A repository disappears from queues, counts, search, selection, and sync scope. The person still needs to find it and bring it back.

01

Visible entry point

Settings stays at the bottom of the work navigation on laptop and narrow screens.

02

Consequences before commitment

The interface names the rows and counts that will change before it removes anything.

03

Ignored never means lost

Ignored repositories remain in settings, including ones with no currently loaded item.

04

Failures keep the old queue

A failed write leaves the previous configuration in force and gives the person a direct retry.

Option 01 · Minimal

One page. One switch per repository.

Fast to build and easy to understand. Each switch applies immediately, with an inline saving state and an undo notice after success.

A settings area with room to grow.

Tradeoffs

The scalable option is the sensible default.

It gives the next known setting a home, keeps saving behavior predictable, and asks for less invention than the search-first direction.

If option 02 is accepted

The decision comment can be exact.

Entry point
Settings is the final row in the left navigation and the compact header control on narrow screens.
Navigation model
A settings section list on laptop becomes a section picker on narrow screens.
Save behavior
Changes remain local to the form until “Apply changes” succeeds. Discard returns to saved values.
Persistence owner
The server stores ignored repository identifiers with instance configuration in SQLite.
Sync + refresh
Account sync keeps ignored work current in the cache. A focused refresh cannot start for ignored work.
Recovery
A failed save keeps the old queue and staged edits. Retry and discard remain available.
Queue behavior
Successful apply recomputes rows, counts, search, selection, scope text, and empty states together.
Next setting
“Queue rules” can hold label-to-queue mapping without changing the settings navigation.
